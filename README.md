# Caption-Express

A local Ubuntu desktop app for making reviewed video/text pairs for LTX 2.3 training. Open one media file, choose any start and end time, position a fixed no-padding crop, and export a new clip. The original is untouched. One selected Gemma 4 E2B or E4B GGUF captions sampled video and the exported soundtrack, with a single editable caption field.

## Quick start

Caption-Express currently installs and runs from its source checkout on an Ubuntu x86-64 desktop. There is no `.deb` or AppImage package. Keep the checkout in a writable folder, open a terminal there, and run:

```bash
bash scripts/run.sh
```

For a clone in your home folder, run `cd ~/Caption-Express && bash scripts/run.sh`. First launch prepares private build, media, playback, and model-server tools inside `.cache/`; it does not install system packages or download model weights automatically. You need an internet connection, enough free disk space, and the host libraries described below. In **One clip → Model and prompts**, choose which Gemma GGUF and matching projector pairs to download into `models/`. You can start with stock E2B to test the download flow. Then create a project and export or caption a clip. Later launches reuse completed downloads.

The source-only checkout intentionally contains no models, exports, datasets, or test videos. The model picker can also discover compatible pairs already present in ComfyUI or LM Studio on the same computer; the **Installed in app** badges refer only to this checkout's `models/` folder. Use those badges to verify a fresh in-app download.

## First-launch setup

On Ubuntu x86-64, `scripts/run.sh` downloads and verifies a private toolchain on first launch: .NET 10.0.402 SDK, Python 3.14.8, and FFmpeg/FFprobe 8.1.3. They live in the ignored `.cache/tools/` folder, and the launcher selects them for the app and its worker. NuGet packages and .NET's CLI state also stay under the project's `.cache/`. The launcher separately prepares private LibVLC playback libraries and includes an English spelling dictionary. No system-wide install or `sudo` is used. Later launches reuse the completed installs. Run `bash scripts/setup-host-tools-local.sh --dry-run` to see which private tools are ready, or run the script without an option to repair them.

The downloads are pinned to exact publisher assets and verified against their published [Microsoft SHA512](https://dotnetcli.blob.core.windows.net/dotnet/release-metadata/10.0/releases.json), [Astral Python SHA256](https://github.com/astral-sh/python-build-standalone/releases/tag/20261013), and [BtbN FFmpeg SHA256](https://github.com/BtbN/FFmpeg-Builds/releases/tag/autobuild-2026-10-14-13-03) digests before extraction. The FFmpeg package is a GPL build because export uses `libx264`; see [BtbN's source and build scripts](https://github.com/BtbN/FFmpeg-Builds) and the [FFmpeg source](https://ffmpeg.org/download.html). The exact archives are intended for Linux x86-64 and need a standard Ubuntu graphical desktop and its native display/audio libraries. The NVIDIA driver, base OS libraries, Bash, GNU tar/coreutils, `curl` or `wget`, and Ubuntu `apt-get`/`dpkg-deb` for private LibVLC extraction still come from the host. A network connection and free disk space are needed for first launch. If private setup fails but compatible host tools are already installed, the launcher explains the failure and can use those host tools; a fresh computer without them receives a specific error. On an offline computer that already has all four host tools, set `CAPTION_EXPRESS_SKIP_LOCAL_SETUP=1` for that launch to defer the private downloads.

On first launch, the script also installs the pinned official Ubuntu x64 CUDA 12.8 llama.cpp server and its matching libraries in the project's ignored `.cache/`. The installer verifies both download SHA256 hashes against [the release provenance attestation](https://github.com/ggml-org/llama.cpp/attestations/52904614) and checks the executable. Allow roughly 1 GB of disk space and time for the initial download. The app uses the project-local server first and can fall back to an installed LM Studio CUDA backend or `llama-server` on `PATH` if setup is unavailable. To retry setup manually, run `bash scripts/run.sh`.

The launcher does not download Gemma weights. In **One clip → Model and prompts**, each of the four choices shows **Installed in app**, **Incomplete**, or **Not installed** for that pair in the app's `models/` folder. Select missing pairs and click **Download selected models**. Select an installed pair and click **Verify selected models** to recheck its pinned SHA256 hashes. Each choice obtains its GGUF and matching projector from the same repository. Transfers run in the background and can be paused and resumed. All four choices together require about 30.1 GB of model storage. Stock E4B is selected by default once installed. Private toolchain setup may take several minutes on a fresh checkout; model downloads are a separate, optional step.

Optional executable overrides are `CAPTION_EXPRESS_PYTHON` and `CAPTION_EXPRESS_LLAMA_SERVER`. The launcher normally gives the worker the private Python interpreter; it does not require ComfyUI's Python environment. A custom `llama-server` with nonstandard shared-library locations can set `CAPTION_EXPRESS_LLAMA_LIB_DIR` to colon-separated directories containing libraries built for that same server. An explicit server override is used alone and fails clearly if it cannot start; unset it to use the automatic fallback order. The app strips the launcher's private LibVLC library paths from the model server's environment.

## Workflow

1. Create or select a named LTX 2.3 project. For a new project, choose **Video + audio** (the default, requiring an embedded audio stream) or **Video only** (audio is removed from exports), plus one video format. These choices are fixed when the project is created. In **One clip**, open a source file and choose start and end timecodes. For video, select a resolution bucket and drag the crop or adjust its position sliders.
2. Select **Export new clip** or **Caption exported clip**. Captioning first makes a new export whenever the selection or crop has changed.
3. In a Video + audio project, the selected Gemma model captions sampled video frames and listens to the exported soundtrack in separate passes. **Refine combined video + audio caption** is optional and starts off; guided clips still receive a final synthesis pass. In a Video only project, the export has no audio track and Gemma captions its visuals. The generated draft appears in the single **Caption** field and is saved beside the export. Older mixed-media projects retain their audio-only file support.
4. After a successful refinement, use **Show initial draft** and **Show refined draft** to compare the exact drafts from that run in the same text field. Compare before editing; the switch disables while the displayed draft has manual edits, so it cannot overwrite them. Only the displayed text is saved. Select **Try another draft** to rerun the same export with modest sampling. A rerun may differ or return the same words, and its details still need review. It appears in the same editable field while the saved `.txt` remains intact. Select **Save caption** to replace the saved text with this draft, or **Discard unsaved edits** to restore the saved caption. The app protects an unsaved draft before another source, export, or caption run.

**Optional guidance for this clip** accepts brief free text or timecoded cues such as `00:00-00:05: A girl crawls through a metal tunnel; breathing and a low hum are audible.` Cue times are relative to the exported clip, where `00:00` is the selected trim start. The visual and soundtrack passes remain separate; for video with audio, a final Gemma pass uses their observations and your notes even when **Refine** is off. Notes stay in the field for reruns, but changing the source, trim, resolution bucket, or crop position requires you to edit or confirm them before captioning. Batch does not use these per-clip notes. Review every draft for unsupported details and timing errors.

Individual and folder runs share the **active project's** working folder, for example `exports/Tunnel Study/Vid-0001.mp4` and `exports/Tunnel Study/Vid-0001.txt`. Each named project has its own sequential names, review states, and duplicate history while it is active. Finalization removes the project and resets that history when no working or unrelated files remain; a retained project keeps its sequence. A project records its LTX 2.3 settings, media type, and video format so a later app update cannot silently change the meaning of its exports. Create a new project to change the media type or video format. The default H.264 MP4 format uses AAC when audio is included; Video only projects omit audio with every format. The matching editable caption is saved as a `.txt` with the same basename. Temporary caption windows and server logs stay under the ignored project-local `.cache/` directory. No subtitles, draft copies, or event scans are placed beside the exports. The hidden `.caption-express/` folder in each active project stores its number sequence and dataset review and duplicate history.

## Folder runs and dataset review

Use **Batch** to choose a source folder and optionally include its subfolders. The run processes eligible files one at a time, in filename order. Video + audio projects skip sources without video or an embedded audio stream; Video only projects skip files without video and remove audio from their exports. These skips happen before duplicate hashing, export, and captioning and are counted separately in the batch status. The run uses the active project's video format, selected Gemma model, prompts, and thinking setting shown under **One clip → Model and prompts**; the Batch tab has its own optional refinement switch. Each source uses its full available range, snapped to an `8n+1` frame count. Video uses the nearest project bucket, the project's automatic frame rate (24 fps unless custom frame rates were added), and a centered fixed crop. The log shows the resulting FPS, frame count, and duration. The source files stay untouched. Batch and individual exports for that project go into the same project folder.

Batch compares the complete file contents to skip exact duplicates within the folder and across completed runs. It does not remove duplicate source files. A run can be canceled; completed export pairs remain available for review. Failed files are reported in the run log, and an incomplete export can be retried on a later run. Batch accepts MP4, MOV, MKV, WebM, AVI, MP3, WAV, FLAC, M4A, and OGG input files.

Open **Edit Dataset** to review working exports. The list starts on **Needs review**; switch its filter to **Reviewed**, **Excluded**, or **All pairs** to resume work later. Selecting a video shows its first frame before playback, plus its actual dimensions, frame rate, duration, and codecs. Edit the displayed caption and choose **Save caption** before marking it reviewed. Ctrl+click adds individual files to the selection; Shift+click selects a range. **Mark reviewed**, **Needs review**, and **Exclude** apply to every selected pair, while saving changes only the displayed caption. A pair without a saved caption or one that violates its project's media type cannot be marked reviewed. Editing a reviewed caption later, including outside the app, returns it to pending review. Excluded working files remain in that project's exports. Review states persist across app restarts. The tab also finds older media/text pairs already in that working project folder. Older mixed-media projects may contain audio-only exports, but only reviewed video pairs can enter a video dataset through this finalization step.

The caption, guidance, and prompt editors check English spelling offline. Misspelled words receive a red underline; right-click one for suggested replacements or **Add to dictionary**. Added words persist in `~/.config/Caption-Express/dictionary-en_US.txt` (or under `XDG_CONFIG_HOME` when set). The spell checker never changes the saved caption by itself. Technical prompt tags and placeholders are excluded; path and timecode fields are not spell checked.

Expand **Finalize reviewed video pairs**, choose a new destination folder outside working exports, and select **Finalize reviewed pairs**. The app copies every reviewed video and its matching `.txt` to that folder and verifies the copies. It writes `dataset.jsonl` with `video` and `caption` fields, using each relative video filename and the reviewed text, and a `training-recipe.sh` to preprocess this LTX 2.3 dataset. The script records the exact bucket list and follows the project's media type: Video only uses `--skip-audio` and calls for a video-only training config; Video + audio requires audio in each finalized video. Review its checkpoint and environment settings before running it. After publication, the app removes **only the working video and `.txt` files used in that finalization**. Pending, excluded, and unrelated files remain. If no working or unrelated files remain, the app removes the empty project folder and its numbering and duplicate history, then clears the active selection. If a used working file changes or cannot be removed, the finalized dataset remains available and the app reports the retained file. An existing destination folder is not overwritten; choose a fresh folder for each finalization.

Finalization counts decoded frames in each copied video and checks the 32-pixel spatial grid and `8n+1` frame rule. An incompatible clip stops publication while its working pair remains available to fix. The generated recipe lists the exact width, height, and frame count combinations in the published dataset, avoiding a shorter preprocessing bucket that would omit captioned events. If clips have the same aspect ratio and frame count but different pixel sizes, the recipe warns that LTX's bucket selector will resize the smaller ones to the larger size.

Video + audio projects reject a video without an embedded audio stream during One clip export and skip it during Batch. They also reject a no-audio pair at finalization. Video only projects accept video with or without source audio, remove any audio stream from the export, and use `--skip-audio` during LTX preprocessing. Remove the audio modality from the training strategy as the recipe instructs. Older mixed-media projects retain the previous manual-review behavior: videos without audio can be finalized, but the stock [LTX T2V LoRA configuration](https://github.com/Lightricks/LTX-2/blob/main/packages/ltx-trainer/configs/t2v_lora.yaml) skips them in joint training. Stream presence does not prove that an audio track contains audible sound; listen during review.

Open **Model and prompts** to download or select a Gemma model. The four app download choices are stock E2B/E4B Q8 and HauhauCS uncensored E2B/E4B Q8; their installed state is shown beside each choice. You may also place compatible GGUF and matching `mmproj` files in `models/`; the app still scans `~/ComfyUI/models/text_encoders/` and `~/.lmstudio/models/` for compatible pairs already present. Use **Refresh models** after manually adding a pair. Stock E4B is the accuracy-oriented default; the E2B `.safetensors` text encoders in ComfyUI cannot be loaded by this llama.cpp backend without a GGUF model and matching projector.

You can edit the single caption user prompt, which is prefilled with the worker default. **Restore default user prompt** resets it. Text inside `[[video: ...]]` controls the visual pass, `[[soundtrack: ...]]` controls the soundtrack pass for video, `[[audio_only: ...]]` controls a standalone audio file, and `[[refine: ...]]` controls the optional final pass. `[[later: ...]]` applies after the first visual section; `[[later_audio: ...]]` applies after the first audio section. The `{previous_caption}` placeholder supplies that pass's preceding caption; the default asks for only new events and suppresses an exact “No new event.” or “No new audio event.” answer. These instructions can be edited or removed; plain text is always sent.

By default the app uses Gemma's chat template without a separate system message. An edited system prompt applies to every Gemma pass. **Enable Gemma thinking** remains on by default; switch it off for a faster draft. The selected model stays loaded across individual captions, reruns, and sequential batch files. **Unload model** releases its process and GPU memory; changing the model or thinking setting, canceling a job, closing the app, or a server failure also unloads it. Editing prompts or guidance does not require a reload.

Gemma receives separate visual and soundtrack requests for video with sound. The visual pass samples up to 16 timestamped frames per eight-second section at a maximum edge of 768 pixels; the soundtrack pass listens to up to 25 seconds at a time. The optional refinement pass combines those observations as text. It is skipped on unguided clips when Gemma produced no usable soundtrack notes, and the app flags the missing audio for review. Guided clips can still use the final synthesis pass with human notes. A failed refinement keeps the initial draft. Quiet audio is raised toward a safe inference level without changing the exported soundtrack; digital silence and faint codec residue are skipped. The worker retries video with fewer frames after a context or memory error. The output frame rate follows the active project; inference sampling is separate.

Audio event times inside a 25-second section are not independently grounded by this backend; add or correct precise sound timestamps manually. A controlled stock E4B test found that adding a cropped frame to the audio pass sometimes suppressed real sounds or suggested sounds that were not heard, even after a stricter prompt. Caption-Express therefore uses sound-only audio requests and keeps user guidance for details you can verify. Refinement remains off by default because it can misplace events. Only the caption in the editable field is saved. [Google's Gemma 4 model card](https://ai.google.dev/gemma/docs/core/model_card_4) documents video and audio input, while [the Gemma 4 launch article](https://huggingface.co/blog/gemma4) says non-speech sounds and music were not part of its audio question-answer training. Review every caption before training, especially music, effects, motion, and event times.

The current llama.cpp audio request places the recording before the sound instructions. A local E4B test showed that text-first ordering sometimes made Gemma falsely claim no recording was attached. If Gemma still makes that claim, the worker removes the refusal from the caption and displays an audio-review warning. For an audio-only file with no usable description, the run fails instead of saving a false silence caption. The warning means the soundtrack needs manual listening; it does not mean the remaining sound words are correct.

## LTX 2.3 project exports

Create one named project for each set of training exports, such as `LTX 2.3 - People` and `LTX 2.3 - Racing`. Choose Video + audio or Video only and a video format when creating it. Working pairs live under `exports/<project name>/` instead of sharing one export sequence. The project records its media type, video format, spatial grid, temporal frame rule, and frame-rate choices. A particular export can still use a different bucket or FPS selected in the app; its actual media properties are shown during review. Use a separate project when you want those choices kept in distinct review queues.

Before making the first export in a project, you can add custom bucket dimensions aligned to the 32-pixel spatial grid and custom frame rates in the project editor. Once the project contains exports, create another project to change its export recipe. Automatic FPS is 24 unless you add custom rates; video frame counts follow `8n+1`.

The nine built-in buckets are 1536×640, 1344×768, 1280×832, 1152×896, 1024×1024, 896×1152, 832×1280, 768×1344, and 640×1536. The app picks the nearest bucket by source aspect ratio, using area to break ties; you may reposition the fixed crop in One clip. Cropping removes excess picture without padding. Batch uses the same automatic choice and a centered crop. Low-frame-rate sources are converted by repeating frames, which cannot recover missing motion. Frame snapping keeps the last sampled picture at or before the selected end. The file's nominal duration includes that final frame's display time, so it can be up to one output frame longer than the last sampled source time. The preview shows both values.

These are **practical export choices**, not a claim that LTX 2.3 accepts only the listed dimensions or frame rates. [LTX's trainer derives its spatial and temporal multiples from the checkpoint's VAE](https://github.com/Lightricks/LTX-2/blob/main/packages/ltx-trainer/docs/dataset-preparation.md); 32 and `8n+1` are its documented default. The chosen codec is separate from the project's bucket and timing settings. **MP4 · H.264 + AAC** is the default; the other available formats are listed below.

## Video export formats

**Video format** names the container and video codec, plus the audio codec used in Video + audio projects. Video only projects omit audio regardless of format. The format choice does not certify that a particular trainer can decode the file. Choose one of five formats when creating a project; **One clip** and **Batch** show the saved choice:

| Format | Typical reason to choose it |
| --- | --- |
| **MP4 · H.264 + AAC** (default) | Widely decodable, moderate file size, and the safest first choice for a video dataset. |
| **MP4 · H.265/HEVC + AAC** | Smaller files at similar visual quality, when the training pipeline supports HEVC decoding. |
| **MP4 · AV1 + AAC** | Efficient compression for storage, with slower export and potentially less decoder support. |
| **WebM · VP9 + Opus** | An open WebM alternative when the training pipeline supports it. |
| **MOV · ProRes 422 + PCM** | Editing-friendly, high-bitrate intermediate with uncompressed audio; much larger files. |

The project video format does not change its frame-count rule or output frame rate. Non-square-pixel sources are normalized to their displayed shape before bucket selection, crop preview, and export. AV1 can take longer to encode and ProRes can consume much more disk space, especially for large batches. Confirm that the target trainer can decode your chosen format.

The [LTX video reader](https://github.com/Lightricks/LTX-2/blob/main/packages/ltx-trainer/src/ltx_trainer/video_utils.py) uses PyAV, while its [embedded-audio loader](https://github.com/Lightricks/LTX-2/blob/main/packages/ltx-trainer/src/ltx_trainer/process_videos.py) uses TorchAudio. None of the five choices is excluded by the trainer's codec logic; the media smoke check decodes video and audio from all five with the app's FFmpeg build. A different training host may have a different decoder build. Check that preprocessing produced audio latents for clips with sound, because LTX currently treats an audio-load failure as missing audio.

The app shows the resulting export size as `width × height × frames`. To use the whole exported clip in LTX preprocessing, choose a matching frame-count bucket; the trainer takes only the first frames when its bucket is shorter than the clip. Long clips at large resolutions can require substantial training memory, so splitting into coherent shorter clips may be preferable.

[Lightricks' dataset preparation guide](https://github.com/Lightricks/LTX-2/blob/main/packages/ltx-trainer/docs/dataset-preparation.md) expects rows with `video` and `caption` fields for video training and can extract embedded audio from the video. Caption-Express writes `dataset.jsonl` and a training recipe for LTX 2.3; finalization preserves the selected MP4, WebM, or MOV video without transcoding it.

## Checks

```bash
dotnet build src/CaptionExpress/CaptionExpress.csproj --no-restore
dotnet run --project tests/MediaSmoke/MediaSmoke.csproj --no-restore
dotnet run --project tests/DatasetCatalogSmoke/DatasetCatalogSmoke.csproj --no-restore
dotnet run --project tests/DatasetFinalizerSmoke/DatasetFinalizerSmoke.csproj --no-restore
dotnet run --project tests/ProjectStoreSmoke/ProjectStoreSmoke.csproj --no-restore
dotnet run --project tests/ProjectWindowSmoke/ProjectWindowSmoke.csproj --no-restore
dotnet run --project tests/SpellCheckSmoke/SpellCheckSmoke.csproj --no-restore
dotnet run --project tests/SpellEditorSmoke/SpellEditorSmoke.csproj --no-restore
python3 -m py_compile worker/caption_worker.py
python3 -m unittest discover -s tests -p 'test_*.py'
```

The media smoke check covers the five video formats, the crop, square-pixel and anamorphic inputs, LTX 2.3 buckets and frame rates, frame-count rules, audio alignment, late seeks, sequential export names, and an unchanged source. The catalog and finalizer checks cover project isolation, duplicate history, review states, JSONL manifests, training recipes, verified copies, and cleanup limited to finalized pairs. Gemma uses separate sound-focused and visual passes, optionally followed by final text refinement. Caption accuracy still requires manual review. The smoke tests generate their own media fixtures; personal benchmark clips are not included in this source release.
